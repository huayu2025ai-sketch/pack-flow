# PackFlow

PackFlow 是一个轻量的打包清单与运输状态追踪工具，适合出差、旅行、搬家和寄送物品等场景。项目使用原生 HTML、CSS 和 JavaScript 构建，无框架、无构建步骤、无后端，全部逻辑在浏览器中完成。首次打开会内置一份示例清单，可以直接修改成自己的内容。

## 功能

### 清单与分组

- 创建、编辑、删除分组，删除前会弹出确认框
- 拖动分组卡片调整顺序
- 为分组设置状态：待准备、运输中或已收到
- 分组支持名称、一句描述和四种颜色（湖蓝 / 杏橙 / 丁香紫 / 苔绿）
- 单独展开或收起分组物品列表，也可一键展开或收起当前视图中的全部分组
- 在分组内直接「添加到这个分组」，并通过进度条和「已完成 / 总数」查看分组进度

### 物品

- 添加、编辑、删除物品，删除前会弹出确认框
- 点击勾选框在「待准备 / 已打包」之间切换
- 在同一分组内拖动物品行排序
- 物品分为 10 个分类（数码产品、服装、小电器、证件、生活用品、文件资料、书籍、家居用品、餐厨用品、其他），可在表单中选择，未指定时按名称自动识别
- 不同分类显示不同颜色的标签
- 可填写备注或追踪单号；新增带追踪单号的物品会把所属分组自动标记为「运输中」

### 筛选与统计

- 顶部统计卡片：总物品、已完成（含准备进度百分比）、运输中分组数、待处理
- 视图切换：全部分组 / 运输中
- 按状态筛选：全部、待准备、已打包、运输中
- 按分类下拉筛选
- 关键词搜索物品名称、备注和分组名称
- 筛选栏可折叠收起

### 体验

- 导入和导出 JSON 备份
- 编辑当前清单名称（只保存在浏览器，独立于清单数据）
- 日间与深夜模式，首次访问跟随系统偏好
- 操作结果以 Toast 提示，删除和导入使用统一的确认弹窗
- 快捷键：`Esc` 关闭弹窗，`Ctrl` / `⌘` + `K` 聚焦搜索框
- 针对手机端优化的响应式布局，最小适配到 350px 宽度

## 数据与隐私

所有清单数据仅保存在当前浏览器的 `localStorage` 中，不会上传到服务器。使用的键：

- `packflow-data`：分组、物品和操作记录
- `packflow-trip`：清单名称
- `packflow-theme`：主题偏好

这意味着：

- 不同浏览器、设备或浏览器用户之间不会自动同步数据。
- 清除浏览器网站数据后，清单可能无法恢复。
- 更换设备或浏览器前，建议使用页面中的「导出」功能保存 JSON 备份。
- 导出的 JSON 同时包含清单数据与清单名称；导入会覆盖当前清单，页面会先校验文件格式并在执行前要求确认。
- 导入文件中的清单名称（如果有）也会一并恢复。
- 兼容旧版本数据：旧的物品「运输中 / 已收到」状态会自动转为「已打包」，缺失的分组状态和分类会自动补全。

## 本地运行

需要 Python 3。

```bash
./run.sh start
```

默认访问地址：<http://127.0.0.1:8080>

常用命令：

```bash
./run.sh status
./run.sh restart
./run.sh stop
```

指定地址和端口：

```bash
PACKFLOW_PORT=9000 ./run.sh start
PACKFLOW_HOST=0.0.0.0 PACKFLOW_PORT=9000 ./run.sh start
```

也可以直接启动静态文件服务：

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

## Docker 部署

项目提供了 `Dockerfile` 和 `docker-compose.yml`。

```bash
docker compose up -d --build
```

镜像标签默认为 `latest`，可通过环境变量指定：

```bash
IMAGE_TAG=20260924 docker compose up -d --build
```

Compose 配置会将服务加入外部 Docker 网络 `npm-network`，适合配合 Nginx Proxy Manager 使用。首次部署前请确保该网络已经存在：

```bash
docker network create npm-network
```

容器内部通过 Nginx 在 80 端口提供静态页面并带有健康检查。Compose 只 `expose` 80 端口、不映射到宿主机，因此需要通过同一网络中的反向代理访问。
